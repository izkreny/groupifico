# Build the Me screen

## Which frames this is built from

Frames 9g "Me", 9h "Edit me" and 9h2 "Edit me - validation errors", read for pattern, copy, control set and states only, per the wireframe-fidelity note the issue and the epic both carry.

9g draws a profile card (initials, full name) and then account rows only: Account, Sign out, Create group, Delete my account, each with the line the issue quotes. 9h draws one form, First name, Last name, Mobile and Email, with one Save. 9h2 draws each error under its field and the summary alert on top.

## What these screens are today

Two scaffolds for one person. `/user` shows the email, the `#solely_owned_groups` block #289 added and the delete sheet; `/user/edit` edits the email through `UsersController#update`. `/user/profile` shows the full name and mobile; `/user/profile/edit` edits first name, last name and mobile through `UserProfilesController#update`. The shell's avatar in `app/views/layouts/_header.html.erb` already links to `/user/profile`, and nothing in the app renders a sign-out control.

## One Save writing two records

`UserProfile` gains `accepts_nested_attributes_for :user, update_only: true`, the pattern `Group` and `Event` already use for `address`, rather than a form object, which `rails-style` rules out. `update_only: true` is load-bearing: without it, nested attributes arriving with no `id` build a new `User` instead of updating the one the profile belongs to (`assign_nested_attributes_for_one_to_one_association` in Active Record). With it, the record written is always `Current.user.profile.user`, so no parameter can name another account, and `user_attributes` permits `:email` alone.

"Skipped when unchanged" is Active Record's own behaviour rather than code to write: autosave saves a `belongs_to` target only when `changed_for_autosave?`, so an unchanged email writes nothing to `users` and `User`'s `after_update` never consumes the outstanding sign-in links. The request spec proves it by the user's `updated_at` standing still. Both writes share the profile's transaction, so a refused email rolls back the name change with it.

Errors on the nested user are keyed `user.email`, which `AppFormBuilder#covered?` treats as drawn once the form calls `fields_for :user`, so an email error sits under the Email field and not twice in the summary.

`UserProfilePolicy` is unchanged: `update?` already answers whether the profile is the reader's own, and the account written is reached through that profile.

## The old routes, and what `UsersController` keeps

`GET /user` and `GET /user/edit` become router redirects to `/user/profile` and `/user/profile/edit`, the way `basecamp_fizzy` retires its own paths. `get "user"` would auto-name itself `user`, which the singular resource's `destroy` route already owns, so the redirect carries `as: nil`. A router redirect answers before `require_authentication` runs, so each of these routes gets one request example rather than the signed-in/signed-out pair: there is no action behind it to be signed in to.

`resource :user` narrows to `destroy`, and `UsersController` keeps `destroy` and its rescue alone, with `skip_verify_authorized` and `set_user` narrowed to match. `update` loses its last caller with the form and goes, with `users/show`, `edit`, `_form` and `_user`. `refuse_ownerless_groups` redirects to `user_profile_path` directly rather than through the router redirect. `destroy`'s success target stays `user_path`, since #179 owns that fix and the request spec's comment says so.

## The block naming solely owned groups stays

The `#solely_owned_groups` alert moves to the Me screen, beside the Delete my account row. It is #289's explanation of why deletion is refused, not a list of memberships, so the criterion's "the reader's groups are not listed here" does not reach it, and dropping it would regress a fix merged this week. `UsersController`'s comment that the account screen names those groups is corrected to say the Me screen does.

## Layout calls the frames leave open

- **Sign out** is the app's first sign-out control: `button_to "Sign out", session_path, method: :delete`, which `SessionsController#destroy` already answers.
- **Save** sits at the bottom beside Cancel, as `groups/_form.html.erb` places it, rather than in the title row where 9h draws it: placement is styling, and the redesigned forms already settled it.
- **Mobile** is one telephone field labelled "Mobile" with the frame's hint; 9h's `+385` segment is incidental.
- **No new validation.** 9h2's "First name can't be blank" has no rule behind it, and adding one is not this issue. The failed-save state is proven with one real error per record: a mobile over 50 characters on the profile and a malformed email on the account.

## Steps

- Add `accepts_nested_attributes_for :user, update_only: true` to `UserProfile`, with its shoulda one-liner in `spec/models/user_profile_spec.rb`.
- Permit `user_attributes: [ :email ]` in `UserProfilesController#user_profile_params`, and extend `spec/requests/user_profiles_spec.rb`: the email written with the name, the account left untouched when the email is unchanged, a malformed email re-rendering 422 with its error under the field, and the block naming solely owned groups moving here from `spec/requests/user_spec.rb`.
- Narrow `resource :user` to `destroy`, add the two router redirects, shrink `UsersController` to `destroy` and its rescue with the refusal pointed at `user_profile_path`, remove `users/show`, `edit`, `_form` and `_user`, and rework `spec/requests/user_spec.rb` for the redirects, the removed `PATCH`, and the refusal's new target.
- Rebuild `user_profiles/show.html.erb` and `_user_profile.html.erb` as the Me screen: the "Me" title row through `shared/page_header`, the profile card with initials and full name, then the four account rows with their lines, the solely-owned block and the delete sheet.
- Rebuild `user_profiles/edit.html.erb` and `_form.html.erb` as Edit me: First name, Last name, Mobile with its hint, and Email through `fields_for :user`, inside `with_error_summary`, with Cancel and Save.
- Repoint `spec/system/account_deletion_refusal_spec.rb` at `user_profile_path`, and add `spec/system/me_spec.rb` for what only a browser adds: the rows and both screens paint in light and dark with no accessibility violations, Account, Create group and Sign out land where they say, Save lands back on Me, and a failed save paints the field errors and the summary alert.
- Run `bin/ci` and tick the boxes.

Every step that writes markup goes through the daisyUI Blueprint MCP server first, per the epic: the `daisyui-blueprint-mcp` skill, then the server's setup, rules and component-syntax tools, the markup, and its quality inspector afterwards. The row list and the profile card are the syntax expert's to settle rather than guessed here.

`spec/system/me_spec.rb` is a new file because no file covers either view: `spec/system/account_deletion_refusal_spec.rb` covers the refusal flow, which only passes through the screen.
